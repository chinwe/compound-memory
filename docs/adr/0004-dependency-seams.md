# 依赖 seam：仅 vector 抽引擎缝（VecEngine），git / filesystem / MCP 维持注入式现状

对 #22 提案建议 4 的显式依赖层（git capability layer / vector runtime / filesystem backend / MCP adapter）逐项裁决，结论为仅 vector 通道抽抽象层：新增平级文件 vector_engine.py，定义 VecEngine 协议（open / close / upsert / remove / update_rel / entries / knn / rebuild / commit——引擎只存不算：content-hash 计算与 embedder 调用留在编排层，对账 diff 归编排层、引擎提供 entries() 快照）与 SqliteVecEngine 实现（vec0 虚表、serialize_float32、L2 距离→余弦换算），vector_index.py 降为纯编排（活性 mtime 基线、带外对账、batch 暂存、降级契约等不变量不动）。两缝正交：换模型动 embedder（模型缝，embedding.py 单点不动）、换引擎动 engine、都不碰编排——这是 vector 与其余三个 seam 的本质差别：sqlite-vec 之外存在可指认的候选引擎（faiss/lancedb/纯 numpy），而其余三者说不出第二实现与消费方。engine 注入点开在 VectorIndex.__init__ 可选参数（默认 SqliteVecEngine），MemoryStore 构造参数零改动，不预设环境变量切换机制（接口留缝、实现不预设）。三层降级守卫归属：SQLITE_VEC_OK 随实现进 vector_engine.py，VEC_AVAILABLE 留 embedding.py，embedder None 判断留编排层 _usable()。其余三个 seam 维持现状：git（git 开关 + git_probe 注入已兑现假探测/无 git 环境测试收益，真 git 语义靠真仓库测最诚实，「审计史 = git log」的产品承诺钉死了 VCS 选型）；filesystem（文件系统是本地优先 spec 的最终事实源，抽象它等于抽象领域本身；原子写 atomic_write_text 单点、删除 remover 注入、mkdir 先判存在三个真坑已各有单点解，FilesystemBackend 换不来任何新注入能力）；MCP adapter（server.py 已是唯一读写边界与错误翻译单点的宿主协议适配器，它是边界不是可换后端）。测试 seam 随拆分收拢三规则：R1 注入面单点——seam 参数只开在 facade.__init__（现有七参数被签名红线锁死），机制/动词模块不开自己的注入参数、需要置换能力时经窄 Deps 传；R2 默认 adapter 跟随宿主模块——_git_available→gitlayer、_unlink_file→files、default_root→paths（#27 已裁），时钟/agent_id 默认装配在 facade；R3 置换两级——store 级（conftest 注入 remover/git_probe/clock，契约与集成测试走真件）+ 模块级（单元测试 fake 窄 Deps），维持禁 patch 全局（shutil.which 教训）。防过度抽象红线逐项核对通过：每个维持现状的 seam 其现有注入都兑现了具体测试/解耦收益，每个不抽的抽象都指认不出第二实现。决议详情见 #28。
