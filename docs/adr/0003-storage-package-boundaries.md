# 存储层拆分边界：storage/ 包、机制与动词都外移、facade 薄组合点、动词侧窄 Protocol

storage.py（1156 行、全库近四成）拆分为 storage/ 目录包共 14 文件：机制层 5 模块（paths 布局与路径推导 / files 的 MD+frontmatter 序列化与按 id 读 / gitlayer 子进程提交与孤儿恢复 / locking 写锁与 batch 协调 / validation 校验与门禁谓词）+ 动词层 7 模块（writing / lifecycle / search / indexing / distill / review / stats）+ facade.py + __init__.py。`MemoryStore` 保留为薄组合点（约 250-300 行）：全部公开方法签名不变、构造装配与锁/commit 收口在 facade、get/link 两个薄动词的方法体留在 facade，其余动词转发到动词模块；`__init__.py` 全量 re-export 旧导入面（default_root / MEMORY_TYPES / DISTILL_* / PROMOTION_* / 统计桶函数等），包外 `from compound_memory.storage import X` 与实例旧有名（index / vector_index / ns_root / `_write_new` / `_scan_pairs` 等测试可达件）零改动。动词模块各自声明窄 Protocol（如 DistillDeps），函数首参收 store——依赖倒置单向（facade→动词模块→Protocol，动词不 import facade），动词间真实依赖链（distill_apply→write_new/_archive、review_resolve→find/_archive）经 Deps 接口解，mypy 静态验证 facade 鸭子类型满足，延续 model.py 拆分打破循环依赖的先例。门禁谓词（_check_ns / _check_ns_owner / _resolve_identity）定义单点收进 validation.py、执行时序一动不动（参数型动词在方法入口、按 id 动词在锁内 find 之后——ns 只有 find 后才知道），红线不变量「按 id 读与门禁也在锁内」保持。被否决的备选：动词留 facade（约 600 行，先例研究中 mem0「只立 seam、编排逻辑不外移致 main.py 持续膨胀」的反面教材形态）；重构提案原始 8 模块直译（文件 IO 与生命周期动词两块职责无归属）；常量集中 consts.py（每个动词 import 穿一层，且与 model.py「TYPE_SPEC 领域表」语义混淆——阈值常量随宿主动词模块走，__init__ re-export 保旧名）；facade 侧统一宽 Protocol（#25 决议否决的宽接口膨胀）。既有平级领域模块（index / scoring / review_queue / vector_index / embedding / liveness / extraction / model）保持平级不归拢。单一定义点核对：scoring.rank 与 model.TYPE_SPEC 不动，写锁与 batch 语义归 locking，门禁归 validation，两份缓存同步收口归 indexing，_write_new 四方共用核心（write / batch / distill_apply / tests）归 writing。迁移策略（characterization 先行、逐片外移顺序）另裁。决议详情见 #27。
