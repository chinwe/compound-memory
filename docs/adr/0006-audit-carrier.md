# 审计载体：git 历史即审计史（消息模板钉契约），读路径不审计，events.jsonl 否决

状态变更审计的载体维持「git 提交历史即审计史」：写路径七个动词（write / feedback / link / archive——decay 与 review-resolve 两路归档 / revive / distill apply / review resolve）加三类特殊提交（batch write / partial、orphan changes recovered、init）的现有 commit 消息格式作为模板表钉进契约文档，作 side effects 锚点（#25 已定契约测试用 git 提交断言，模板防漂移）；消息只含 id / ns / type / agent 名，不含正文（隐私约束）。检索评分可解释性排除出审计范围——search 结果 hit 已自带 score / similarity / confidence / uses 分项字段（scoring.rank 形状单点），更细分项（recency / type 权重贡献）要动 hit 形状，撞「MCP 返回形状不变」红线且撑大宿主上下文；未来观测需求走 debug 级结构化日志，不进返回。读路径（search / get）明确不审计：读无状态变更，进 git 是空 diff 噪音，高频检索会把写变更信号从审计史冲掉。观测性统一走结构化日志 debug 级、仅观测不回放不持久。被否决的独立 append-only 事件日志（events.jsonl）：与 git 历史构成第二真相源（写路径全部状态变更 git 已记）、search 级高频事件的体积增长无界（膨胀快过记忆库本身）、与「审计史 = git log」产品承诺冲突。针对 git 膨胀质询的补充裁决：feedback 等高频写动词维持每次一 commit——审计完备性由三层消费端手段保障（按记忆查审计走 git log -- <file> 天然降噪；frontmatter 的 validated_by / uses / confidence / last_used 本就是数据侧审计；CLI git-log 命令加 --exclude / --grep 过滤 flag——MCP git_log 不动，返回形状红线），膨胀量级实测外推当前使用（每天 <20 次 feedback）年约 20-40MB、设计规模高频假设（百次/天）年约 100-180MB，git 纯本地无同步成本可接受，真到量级再裁。local-first 相容（无外发通道、事件内容不出本机）。决议详情见 #31。
