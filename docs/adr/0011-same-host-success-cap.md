# 同宿主 success 累计封顶:折算表加饱和一行,host_bumps 持久配额;diversity 进排序与独立单位扩 project 均否决

(#96 P1-1 剩余 delta,2026-10-18 grill 定稿;立论为**预防性**——真实库未观察到「单宿主刷高挤占多宿主记忆」的失效,故只做不碰检索红线的最小手术)ADR-0007 折算表新增一行饱和语义:每条 success = base **+0.1** + 新验证宿主首验 **+0.15**(数值均不变),但 base 部分按「宿主 × 记忆」累计授予,单宿主累计不超过 **CAP=0.3**——到顶后该宿主的 success 照常记账(uses / success_count / recent 明细 / validated_by),数值不再抬;跨宿主首验 +0.15 不占任何宿主的 base 配额(独立性奖励,天然受宿主数约束);failure −0.2 可累计、contradiction 冻结、obsolete 归档、地板 0.05 / 封顶 1.0 全部维持;配额 **gross 口径**(只累计已授予增益,failure 不归还、不重挣);+0.1 步进与 0.3 整除,无部分授予。效果:单宿主置信天花板 0.5→0.8,0.8 以上只能靠跨宿主验证——「泛化需要不同宿主」由折算表结构性保证,排序经现有 conf 槽免费继承,检索权重与 hit 形状零改动。数据面:证据块(frontmatter evidence,运行时置信度计算唯一数据源)新增 **`host_bumps`** 映射 agent→累计已授予 base 增益(有界于宿主数,frontmatter 增量几个字节);字段缺失读空映射,惰性迁移与证据块同型(不重写全库、存量 confidence 原样、首次 feedback 落块时写入)。**否决的备选**:①**diversity 作为独立维度进检索排序**(confidence × evidence_diversity 乘积/加权和)——先验在两条路径均只 tie-break(词面 0.15 / RRF ε0.04),加维度要么无感要么必须调权,直接撞「先验不得翻过 sim 主序」红线(recall-audit 失效模式②的根治线)与 ADR-0007「检索定权不动」;源头修完后排序免费继承,重开此议需先有观察到的失效 + recall-audit 级证据。②**独立性单位从宿主扩到 project**——project 是调用方自报上下文(ADR-0010),证明力弱于宿主进程身份;观测面已存在(stats 的 cross_validated、search explain 的 validated_by)无需新面;ADR-0008「独立 = 不同宿主的直接使用证据」维持原裁决。③**递减折算曲线**(+0.1/+0.05/+0.02…)——多一组曲线参数、收益不比硬上限多,且同样需要持久按宿主计数。④**net 配额**(failure 归还)——failure 不按宿主记账,归还无诚实归因依据。**既有事实**:ADR-0007 落地时「correctness/usefulness 分维、四维全量」列 future,本决议不提前任何一维——变的只是同一标量的授予规则,不是维度模型。**实施面**:敏感区 TDD——feedback 折算饱和行为先红后绿(同宿主配额尽后数值不动记账照走 / 新宿主首验不受他宿配额影响 / 存量无字段惰性空配额起算 / failure·contradiction·obsolete 逐位不变);既有钉「+0.1 每次」的 characterization 按显式契约变更流程调整并声明;排序管线零改动、无 eval/LongMemEval 依赖;实施票 #99(ready-for-agent)。CONTEXT.md Confidence 词条已同步饱和语义(本次)。
