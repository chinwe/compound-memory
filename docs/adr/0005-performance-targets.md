# 性能定标：三档预算 + 热点做/不做清单——token stats 做宽查询、共享 scan 做对账，其余明确不做

设计规模 1 万条活动记忆（perf-bench 千条基线 ×10，基线 2026-10-03 macOS / 2026-10-04 Windows 复测，见 experiments/perf-bench/README.md）。定标三档：交互读路径（search 各路）万条 ≤2s——MCP 工具调用宿主在等；写后首查对账 ≤5s——一次性成本（后续查询不再付），容忍高一档；运维路径（rebuild-index / stats / distill-plan，launchd 非交互或显式命令）不设数字目标只监控——设目标会诱导不看场合的优化；优化动手前先跑万条档 bench 验证线性外推（先测量后优化）。六热点逐项裁决：① KNN 逐 hit find() 已修结案（直读 rel_path），子项 _active_neighbors 逐 hit find() 明确不做（约 1/3 成本、消它需要路径索引，等万条实测说话）；② 跨进程增量对账做——手段是词法/向量两缓存共享一遍 scan（对账剩余构成里两遍 scan 是已点名的大头），目标万条 ≤5s；③ 全量 rebuild 不做专项——运维显式命令，线性外推 77-200s 可接受，bench 补万条档验证即可；④⑥ 宽查询/大候选集做——手段是 Index 扩展 per-doc token 频表（tokens.json schema 加字段，search 候选路径免 parse 全文、BM25 直接用缓存 token stats），目标万条 broad ≤2s；ns 前缀剪枝已在、rglob 已被基线证明便宜。token stats 与「索引即缓存」哲学一致：缓存可重建、损坏自动降级不报错的不变量保持，检索结果不变（只是 BM25 的计算来源从即时 parse 换成缓存字段）；副作用 tokens.json 变大（万条估几 MB）。⑤ 手写 yaml 快速路径明确不做——CSafeLoader 已吃掉 40-59% 的 parse 成本，剩余收益配不上手写 parser 在怪文件回退上的正确性风险；重复 parse 经 ②共享 scan 与 ④token stats 消减。stats/distill 全库扫不做专项（launchd 非交互，共享 scan 顺手受益）；feedback/write 恒定 200-360ms 不随 N 增长，观察即可。做的优先级：宽查询（交互热路径最痛，千条 1.01s 外推万条 ~10s 远超预算）> 对账（外推 ~30s 同超）。被否决的备选：进程级 Memory parse LRU 缓存（失效正确性风险——mtime 粒度对 atomic_write_text 原子替换，且缓存解析结果与「索引即缓存」的单一缓存哲学有张力、两套缓存活性各自维护；待 token stats 落地测量后再议）；全路径统一预算（运维路径被迫优化）；不定量只看趋势（优化无停止条件）。实现细节（token stats schema、共享 scan 的函数形态）交 to-spec 展开为可执行计划。决议详情见 #30。

实施后注记（spec #33 落地实测，用户裁决接受）：万条实测对账 5140ms，较 ≤5s 预算超出 2.8%——剩余大头是一遍 scan 的 yaml parse，手写快速路径已被本 ADR 否决，不再另开优化手段，预算按实测接受；broad 522ms（≤2s 达标）、narrow −89%、semantic −65%。已知代价：tokens.json v2 缓存使 seed +64% / feedback +17%、万条约 22MB（批量灌库正门仍是 batch 通道）。
