# 置信度：证据驱动的可降模型（feedback 带 outcome、单字段重定义+证据块、混合三层留痕）

spec:52-57 的单调置信度公式（conf = min(1, conf₀ + 0.1×uses + 0.15×跨Agent)）自本决议起取代——它只有上升通道，"被用得多"会伪装成"正确"。检索侧定权不动：词面权重 0.70/0.15/0.10/0.05 与 RRF 先验配比（vec-spike 定权，spec:52-57 的检索部分）维持，变的只是 conf 数值的**来源规则**。confidence 语义重定义为**证据正确性**（evidence correctness），由反馈事件折算、可升可降；usefulness 继续由 uses/last_used 承载（提案 §1 的四维模型不做全量落地，correctness/usefulness 分维列 future）；feedback 一等公民契约（spec:49）不变。`memory_feedback` 签名扩展可选 `outcome` ∈ success（默认，老调用方零破坏）/ failure / contradiction / obsolete / unknown，未知值按调用方错误抛 ValueError——MCP 恰好 5 tool 契约不动（参数扩展非新 tool）。折算表：success +0.1、跨 agent 首次 +0.15 沿用（`validated_by` 保留，其去重职责是明细 cap 承担不了的）；failure **−0.2**（负面不对称：错误记忆被复用的代价高于未验证记忆被搁置的代价，重复 failure 累计折算）；contradiction **数值冻结**并登记 review 队列（冻结期不升不降）；obsolete **无条件立即归档**（不引入「obsolete 但未归档」中间态，复活走 feedback 自动复活既有通道）；unknown 仅记事件不动数值。下限地板 0.05（保持可检索、可复活），封顶 1.0 沿用；归档规则不新增（TTL decay 通道不变）。留痕**混合三层**：①frontmatter 证据块 `{success_count, failure_count, contradiction_count, last_verified, recent}`（recent 为最近 10 条 `{date, agent, outcome}` 明细）是运行时置信度计算的唯一数据源——明细 cap 10 条防 yaml parse 膨胀（perf-bench 实测 parse 是延迟大头），老明细语义化进计数不丢失；②全史审计靠 commit 消息模板扩展 `feedback {id} by {agent}: outcome=<o> uses=<n> conf=<x>`，`git log -- <file>` 按记忆降噪可查——与 ADR-0006「git 历史即审计史」完全兼容，events.jsonl 维持否决不重开；③frontmatter 的 validated_by / uses 本就是数据侧审计（0006 已裁定）。contradiction 的队列与裁决：ReviewQueue 新增独立行型 `- <date> contradiction <mem_id>: by <agent> (<note 前 40 字>)`（行格式单一定义点内扩展，契约测试同步）；review-resolve 裁决二选一——维持原记忆有效：解冻 conf 并把该次 contradiction 折算为 failure −0.2；裁决原记忆确错：归档之（沿用 review_resolve 归档语义）。存量迁移**惰性**：无证据块的既有记忆读取时缺省视为 `{success_count: uses, failure_count: 0, contradiction_count: 0}`（uses 无差别映射 success——诚实反映「只知被用过」），首次 feedback 时才落盘写块；无全库改写、无版本字段。实施按敏感区 TDD：折算表逐 outcome 钉死（含地板/封顶边界、惰性缺省块、队列行型 roundtrip、契约测试）。实施 PR 同步面：spec:52-57（公式）/58（复利来源①④表述）/61（生命周期状态机的「强化由 uses/confidence 表达」补 evidence 语义）、CONTEXT.md Confidence / Review queue 词条（本决议落地时已同步）、SKILL.md feedback 用法、docs/agent-integration.md 工具表。决议详情见 #43。
